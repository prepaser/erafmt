## Layout and structure

The formatter uses four ASCII spaces per structural level. Function headers (`@...`) are at column zero. ERB declarations beginning with `#` are one level inside a function; ERH directives remain at column zero. A DIM/DIMS declaration requires a name. Local REF declarations can omit zero dimension sizes while preserving their comma count, including proven zero spellings such as `0x0`, `+0`, and `(0)`. Nonzero literal dimensions in a trusted local REF declaration are unsupported. Ordinary DIM/DIMS direct string dimensions, sizes outside 1..1,000,000, more than three dimensions, or a proven total capacity above 1,000,000 produce advisory `suspicious_dimension` warnings and preserve the declaration; a declaration-name macro can change a raw dimension into an initializer. Unresolved macro-capable dimension fields stop subsequent role checks; general arithmetic is not evaluated for capacity. Empty LOCALSIZE/LOCALSSIZE directives produce `missing_local_size`, repeated proven valid non-event integer constant expressions produce `duplicate_local_size`, and nonempty directives in exact runtime event names produce `event_local_size`; constant values outside 1..2,147,483,646 produce `suspicious_local_size` and preserve the directive. The empty-value check runs before the event-function ignore path. Warnings do not change exit codes. Labels beginning with `$` follow the statement depth and never create a block. The formatter understands IF branches, loops, NOSKIP, TRY/CATCH, SELECTCASE/CASE, data blocks, function lists, SIF, and trusted bracket preprocessor regions.

SIF adds one temporary level to its next eligible logical instruction. Proven assignments and prefix/postfix increments have the structural SET role, including debug-only SIF pairs and common paths where preprocessor branches converge. Continuation delimiters are indented with their statement, while continuation interiors remain opaque by default. Without an explicit separator, structural inference requires a proven boundary in the first physical row; a token ending at a row boundary can still be extended by the separator. Opening delimiter lines accept the runtime's Unicode trailing whitespace without changing those bytes; leading whitespace still follows the selected grammar option. The rows are joined only for syntax analysis; syntax edits retain their interior indentation and physical boundaries. Literal payloads, string text, Unicode whitespace, data payloads, plain assignment RHS text, source case, and numeric spelling are preserved. Exact marker and alias text is also preserved. L001-L007 and F001-F002 control ordinary blank lines, comments, final newlines, and line endings.

## Declarations and function headers

Proven ordinary DIM/DIMS declarations with an omitted dimension produce `unsupported_syntax`; local REF omissions and macro-dependent dimension roles remain preserved. Exact uppercase builtin and runtime-reserved names are unsupported as DIM/DIMS names. Private ERB declarations beginning with a BMP Unicode decimal digit remain preserved because header macros can change their declaration role or name; they do not establish a declaration identity or dimension roles. Global ERH declarations and supplementary-plane leading digits keep their runtime behavior. DIM/DIMS initializer type and count mismatches, missing CONST initializers, REF or CHARADATA initializers, multidimensional initializers, and empty initializer values produce advisory `suspicious_initializer` warnings and preserve the declaration. Initializer cardinality uses bounded integer constant dimension expressions: CONST requires exactly the declared size, and ordinary one-dimensional initializers cannot exceed it. Unknown dimensions or initializer expressions defer these checks. Identifier sequences that can expand into declaration modifiers, names, or an initializer operator preserve the declaration without establishing a duplicate-tracking name. Proven modifier conflicts and invalid ERB/ERH modifier scopes produce `unsupported_syntax`; configuration-dependent storage rules remain unresolved.

Function boundaries are accepted only after checking the name, balanced signature delimiters, defaults, and the comment tail independently of rule selection. Square-bracket function subnames such as `@F[1]` are invalid headers and preserve the complete file. One trailing comma after a signature argument is accepted; leading, interior, or doubled empty arguments are rejected. Malformed headers leave the whole file unchanged. Runtime-dependent headers preserve the file except for global F001/F002 rules. ERB declarations must be in the leading function prologue; misplaced declarations protect their containing region and produce `unsupported_declaration`. ERH accepts only `#DEFINE`, `#DIM`, and `#DIMS` at file scope. ERH `#FUNCTION(S)`, `REF` declarations, ERB-only directives, unknown sharp directives, and bracket preprocessing produce unsupported diagnostics and preserve the file except for F001/F002. Repeated `GLOBAL` modifiers remain valid. Exact uppercase builtin and runtime-reserved names used as declaration names are unsupported; exact duplicates within one trusted function or ERH file produce `duplicate_declaration`, while case variants, macros, aliases, and uncertain conditional paths defer. Duplicate tracking requires proven valid constant dimensions and initializers; rejected or unresolved values do not establish a declaration name. String initializer proof is limited to literals with optional parentheses. One terminal initializer comma is ignored for counting while every source comma is preserved. Proven ERH CHARADATA dimensions above two produce `suspicious_dimension`. S012 normalizes only object #DEFINE keyword/name/body separators; its body stays byte-preserved. Preprocessor directives allow ASCII padding and ordinary comment tails; other suffixes produce an unsupported diagnostic and preserve the file except for F001/F002.

Trusted ERB functions warn about duplicate or conflicting #SINGLE/#LATER/#PRI/#ONLY attributes and ignored event attributes outside events. #ONLY overrides earlier event attributes. Repeated #FUNCTION(S) declarations warn, and conflicting function kinds are unsupported. Trusted METHOD declarations whose function names start with a BMP Unicode decimal digit are unsupported and preserve their function; ordinary Unicode digit-leading functions and supplementary-plane digits remain accepted. Conditional or optional declarations and unproven #FUNCTION(S) tails defer state tracking. Bare method declarations honor the configured grammar whitespace. Event recognition uses the runtime event-name set; case variants retain configuration-dependent preservation without event warnings. TRYGOTOLIST FUNC rows cannot carry proven nonempty subnames or arguments; other TRY list variants retain their argument grammar.

When expression parsing is enabled, function signature roles receive a separate semantic check. Proven literal or immutable parameter destinations, invalid numeric constant defaults/indexes, ARG/ARGS default type mismatches, and defaults on other known system variables produce `unsupported_syntax`. Known multidimensional parameters require all indexes, and character parameters require an explicit constant target; bare ARG/ARGS and other non-character rank-1 parameters retain implicit zero indexes. The header remains unchanged while the trusted function boundary, body, and following functions remain available for formatting. Proven runtime builtin defaults/indexes are rejected separately from read-only metadata; constant CSV and GAMEBASE values remain accepted. Exact builtin destinations with reduced constant indexes produce advisory `duplicate_parameter` warnings. Configured continuation headers use the same check with physical diagnostic positions. A physically complete signature sealed by an ordinary comment receives this check even without a continuation separator. Private variables, calls, scoped references, named CSV indexes, and macro-capable fields defer this check; positional proof stops at unresolved fields.

Function and goto names follow the runtime's identifier spelling, including names beginning with Unicode digits. Marker-only header tails such as `@F;!;` are trusted boundaries and retain their original bytes. A marker tail containing executable tokens is preserved with an unsupported diagnostic when its grammar or configuration cannot be proven.

Call targets retain complete backslash escape sequences, including escaped ASCII space and TAB. Escaped commas, parentheses, brackets, and semicolons remain literal target characters. Argument formatting starts at an actual delimiter, and only a proven comment delimiter enables comment layout. These boundaries also apply when an explicit continuation separator joins an escape to the next physical row.

Known non-comment tokens after a parenthesized call argument list produce `unsupported_syntax` and preserve the argument body. Unresolved macros, FORM arguments, and executable markers defer this check when they can change the argument boundary.

## Preprocessing and conditional paths

Malformed preprocessor forms that the runtime handles as warnings produce `Unsupported` diagnostics and preserve the entire file except for F001/F002. These include nested `SKIPSTART`, unmatched closers or branches, repeated `ELSE`, empty or unterminated directives, and unclosed preprocessor regions. IF/ELSEIF conditions must be one runtime identifier token; Unicode and digit-leading tokens remain accepted, while punctuation, quoted conditions, and extra operands preserve the file as unsupported. The formatter does not infer their branch state. Exit code 2 still reports incomplete formatting; `--utf8` may convert the preserved text. Independently detected fatal errors, such as an invalid function header, still prevent all formatting and encoding changes.

Additional branches after `ELSE` or `CASEELSE` produce advisory `branch_after_final` warnings and continue formatting, matching the runtime. Unconditional nested `REPEAT` blocks produce `nested_repeat` warnings; proven nonpositive counts produce `nonpositive_repeat`. A merged preprocessor path also retains an active REPEAT fact when every branch has a proven positive count. Pending SIF diagnostics use the common merge location when branch origins differ. Exact duplicate `$` labels in a trusted function produce `duplicate_label`, including complete explicitly joined labels with physical diagnostic positions. Unknown optional or preprocessor paths suppress these warnings.

With an explicit continuation separator, a complete logical instruction can establish the same repeat, final-branch, and DATA facts after syntax and physical edit mapping are proven. Marked, aliased, preserved, or ambiguous rows defer those facts; conditional metadata still requires agreement across every possible branch.

Adjacent debug-only SIF/target pairs retain their complete lines when both debug modes leave the same structure, allowing subsequent statements to be formatted. Conditional ELSEIF insertion and final branches followed immediately by a common unconditional closer can also retain a proven surrounding structure.

## Expressions and FORM

Expression spacing applies to recognized common expression grammars, including conditions, RETURN/RETURNF, FOR and list fields, calls, compound assignment RHS expressions, declarations, signatures, and proven FORM islands. Qualified variables such as `LOCAL@FUNC:0` use the same expression rules as ordinary variables. Exact known global builtin references such as `RESULT@FUNC` are invalid; only ARG/ARGS/LOCAL/LOCALS permit this qualifier. Unknown names and macro-dependent references remain unresolved. Bare conditional FORM atoms such as `\@ A ? yes # no \@` are recognized without adding quotes or changing literal branches; the false branch may be omitted.

Binary and ternary operators, unary operators, commas, delimiters, indexes, CASE `TO`/`IS`, and remaining token gaps are normalized only after lexical proof. Proven closed builtin calls and compound expressions reject invalid operator suffixes such as `ABS(1)++`, `ABS(1)!`, and `ABS(1)+`; mutable parenthesized variables such as `(RESULT)++` remain valid, while unresolved calls and macros defer these checks. Numeric tokens follow runtime integer overflow rules, including signed decimal magnitude checks, 64-bit binary/hexadecimal reinterpretation, and exponent parsing; numeric spelling is preserved. PRINTV rejects omitted leading or interior fields while allowing one trailing comma, empty raw string atoms, and no arguments. Apostrophe-prefixed raw fields remain byte-preserved and do not count as expression token text, including during conditional structure checks. FORM islands include quoted `@` strings, PRINTFORM, DATAFORM, RETURNFORM, CALLFORM, PRINTV, and nullable REUSELASTLINE contexts; literal spans, escapes, width/alignment fields, and placeholder edge padding retain their own boundaries. Placeholders require a nonempty first expression and accept at most three top-level fields. An alignment field requires a nonempty width; one trailing empty field is valid. Direct non-identifier alignment fields produce a diagnostic and remain unchanged. Exact system names RESULT/RESULTS/CFLAG/CSTR are invalid alignments when preceding field roles are proven. Known LEFT/RIGHT alignment roles reject punctuation tails such as `RIGHT+1`; identifier-only tails and unknown alignment macros remain deferred. Malformed quoted and conditional FORM expressions produce diagnostics when expression parsing is enabled.

Single ordinary quoted literals in the PRINTFORMS family and direct builtin STRFORM statements use the existing FORM spacing rules after their argument checks, including EMEE PRINTFORMSN. Nested STRFORM calls remain unresolved because user functions can override them. For example, `PRINTFORMS "x { 1+2 }"` becomes `PRINTFORMS "x {1 + 2}"`. Outer quotes and literal text remain intact. Source escapes, concatenations, dynamic values, aliases, and markers keep their existing handling; escaped ordinary literals are not reinterpreted. FORM braces require numeric values, percent islands require strings, and widths and conditional expressions require integers. Proven type mismatches preserve the affected island with a diagnostic; neighboring valid islands can still format. Unknown macro-capable tokens, including variable indexes, suppress type inference. DEBUGPRINTFORM/DEBUGPRINTFORML payloads remain byte-preserved without FORM parsing or semantic diagnostics because normal runtime mode discards their arguments; active debug mode can impose stricter requirements.

A proven numeric curly FORM field with a constant width whose runtime 32-bit cast is negative produces an advisory `suspicious_form_width` warning and preserves that island. Neighboring valid islands still format, and independent syntax errors still produce their normal diagnostics. The same warning applies inside proven graphics arguments, including nested FORM strings. For example, `{1,2147483648}` warns, while `{1,4294967296}` wraps to zero and remains valid. Percent string widths use different runtime semantics and do not receive this warning; unresolved values, calls, and dynamic widths defer it. No maximum positive width is imposed.

Literal-only expressions and proven expressions composed of exact builtin variables receive bounded completeness and compound type checks without evaluating values. Builtin type proof applies in formatter context, including compound expressions with parenthesized or indexed builtins. A complete indexed builtin keeps its value type through parenthesized or builtin-only index expressions, including inside compound expressions. Proven invalid index types, arity, and expression shapes propagate through compound indexes instead of becoming unknown. Bounded numeric indexes also retain exact readonly builtin identity in mutable command roles; index domains remain unresolved. Complete builtin increment operands also receive type and mutability checks, including string operands with proven parenthesized indexes; increments inside larger expressions, calls, qualified references, unresolved indexes, and excessive nesting defer proof. Ordinary expressions, compound assignment RHS expressions, call and METHOD arguments, PRINTV, and FORM islands share bounded shape checks for adjacent operands in either order, assignment operators, invalid builtin dot, colon or bracket boundaries, malformed indexed suffixes, incomplete operator operands, string prefix/postfix increments, and misplaced CASE keywords. CASE accepts numeric mutable prefix/postfix increments in IS/TO operands and rejects `?`/`#` as IS operators. It also rejects nested IS/TO, reserved TO used as an unparenthesized builtin index, and grouping parentheses containing commas, while possible function-call arguments remain deferred. Unknown identifiers, mandatory markers, bare calls, scoped references, and deeply nested expressions defer this proof; invalid FORM islands remain separate from valid neighbors.

## Commands and METHOD contracts

Call and jump targets retain literal U+3000 at their edges, including before argument delimiters and comments, even with `--allow-fullwidth-space`. Only ASCII space and TAB are padding around a target. Expression arguments still use the configured grammar whitespace.

The formatter covers common command families for colors, fonts, buttons, waits, character and array operations, string and HTML helpers, calls, jumps, and FORM-producing commands. It uses field-specific parsing for mixed variable/expression arguments and keeps uncertain or dialect-specific forms opaque. EMEE enables the `PRINTN`/`PRINTVN`/`PRINTSN`/`PRINTFORMN`/`PRINTFORMSN` command variants when that dialect is selected. Exact dialect allowlists also cover builtin METHOD functions: common mode uses the base/modern intersection, the base dialect has 160 direct names, and the modern dialect has 266. 151 shared METHOD contracts and 93 EMEE additions or overrides check proven argument counts and types in direct statements, including bounded nullable suffixes and EMEE REPLACE mode arguments. Alternative signatures preserve exact accepted shapes: SPRITECREATE takes two or six arguments, and EMEE GSETFONT takes three or four. GSETFONT and GSETPEN retain their dialect-specific arities; one terminal comma remains valid. MIN/MAX accept numeric variadic arguments; GROUPMATCH/NOSAMES/ALLSAMES check matching proven types. SAVETEXT/LOADTEXT use numeric file indexes in common/base mode and permit string paths in EMEE; common/base reject explicit optional nulls. EMEE also validates SETVAR/VARSETEX, bounded data-table calls, ENUMFILES, MOVETEXTBOX/RESUMETEXTBOX, and GETMETH(S) scalar prefixes, deferring dynamic target and reference semantics. GDRAWSPRITE/GDRAWG accept bounded numeric 2D/3D matrix references; EMEE GDRAWG alone permits an explicit empty matrix tail. Graphics defer call return types because user methods can override builtin names. GETNUM requires a variable reference and a string keyword; EMEE permits an optional third numeric scope field that must have a value when present. FINDELEMENT/FINDLASTELEMENT validate a one-dimensional array and a value of the same type; ARRAYMSORT requires mutable non-character arrays, with a one-dimensional first array. Secondary arrays may have up to two dimensions in Emuera1824 and three in EMEE; common mode retains the modern secondary-array shape. RAND, SUMARRAY/SUMCARRAY, MATCH/CMATCH, INRANGEARRAY/INRANGECARRAY, and STRJOIN validate their bounded reference and optional field roles. STRJOIN rejects proven character-backed string arrays; numeric character arrays are rejected only when an explicit positive range length proves the incompatible consumer path. MAXARRAY/MINARRAY require numeric one-dimensional arrays; MAXCARRAY/MINCARRAY also require character data. All four accept read-only arrays and up to two optional numeric bounds. GETBIT checks direct integer bit indexes against 0..63; calculated or unresolved indexes defer range proof. Read-only arrays remain valid for read roles, and character methods accept the runtime's character ranks. CSV lookup methods check their required numeric fields and optional SP-character flag. FINDCHARA/FINDLASTCHARA check a character-data reference, a value of the same type, and optional numeric bounds; FIND_CHARADATA accepts zero fields or one string pattern. INRANGE* requires both bounds; Emuera1824 accepts its ignored sixth field, while common/EMEE accept at most five. EMEE also checks the two-, three-, and four-field REGEXPMATCH variants, DT_SELECT output references, and XML_GET/XML_ADDNODE/XML_REMOVENODE with their BYNAME variants. EMEE INRANGECARRAY requires one-dimensional character data; common/base retain multidimensional character references. Proven REPLACE mode 1 requires a mutable non-character one-dimensional string array. Whole-array outputs in REGEXPMATCH, XML_GET, DT_SELECT, DT_TOXML and data-table array variants reject character backing storage; scalar XML mutation targets remain compatible with CSTR. Array output roles use the backing variable rank, so indexed forms such as RESULT:0 and RESULTS:0 remain valid. Provided output and numeric flag fields must not be empty when the runtime dereferences them. Scoped names, user declarations, and dynamic indexes defer reference proof. Other runtime METHOD names are recognized for syntax and remain conservative about types. Unknown names do not fall back to METHOD parsing, and explicit handlers or raw commands take precedence.

Optional argument counts permit omission without making every supplied field nullable. HTML_GETPRINTEDSTR's optional line number and EMEE VARSETEX range fields must have values when supplied. EMEE rejects empty consumed flags, output references, and data-table column names or array references; SAVETEXT/LOADTEXT flags must have values for both numeric indexes and string paths. DT_CELL_SET values, DT_SELECT filters, and DT_ROW_ADD row values remain nullable. GDRAWTEXT retains its three-field measurement form, including an unused empty third field; its four-field coordinates must have values. GDRAWGWITHROTATE takes three or five fields, and HOTKEY_STATE requires two.

`CALLSHARP`, `FORCE_QUIT`, `FORCE_QUIT_AND_RESTART`, `QUIT_AND_RESTART`, `SKIPLOG`, `TRYCALLF`, and `TRYCALLFORMF` require EMEE. A name unavailable as an instruction in the selected dialect can still form an implicit assignment when its LHS is proven. `OUTPUTLOG` uses the no-argument instruction grammar in common/base mode, preserving extra payload, and the METHOD grammar in EMEE.

Modern-only METHOD names such as `XML_GET` can also be variable names in the base dialect. Assignment and increment recognition remains consistent across command-separator spacing, including optional SIF targets.

Shared handlers recognize no-argument color, font, save, reset, and restart commands, and optional integer arguments for `AWAIT`, `INPUTMOUSEKEY`, and `RANDOMIZE`. `BEGIN`, `CALLEVENT`, `ALIGNMENT`, color-name commands, `STRLEN`, and `STRLENU` consume raw strings: their command separator and complete payload, including semicolons and trailing whitespace, are preserved. Parenthesized variable arguments such as `TIMES (A:0), 0.5` and numeric unary-plus variables such as `TIMES +RESULT, 0.5` use the existing expression spacing rules. Variable roles reject bracket indexes and residual arithmetic such as `VARSET RESULT:0+1, 1`; `VARSET RESULT:(0+1), 1` is valid, and general expressions such as `RETURN RESULT:0+1` retain their arithmetic meaning. `VARSIZE` reads a bare array identifier and rejects the `RAND` pseudo-array. ADDCHARA, ADDSPCHARA, ADDCOPYCHARA, PICKUPCHARA, DELCHARA, and SAVECHARA validate their full argument lists without a 255-field limit. Proven ignored suffixes on fixed-arity commands produce `ignored_arguments` and preserve the complete command body; macro-dependent names and fields retain their conservative handling. The suffix is ignored text, not a dimension argument. EMEE adds sound, tooltip, HTML island, and background commands; `DT_COLUMN_OPTIONS` parses `DEFAULT` keyword/value pairs and permits one terminal comma, while `SETBGIMAGE` and `REMOVEBGIMAGE` format only proven islands within their FORM fields.

## Graphics

EMEE `SETBGIMAGE` and `REMOVEBGIMAGE` consume one command separator and skip only ASCII spaces before their first FORM field. Any remaining TAB or U+3000 is literal image-name text. A TAB-only or U+3000-only field is nonempty; an ASCII-spaces-only field is missing. Semicolon separators remain unchanged.

Graphics handlers are conservative. The base/common `PRINT_IMG` form accepts one string expression, `PRINT_RECT` accepts one or four safe expressions, and `PRINT_SPACE` accepts one; valid trailing commas are retained. Base/common graphics reject proven numeric image names and proven string values in numeric fields, while EMEE retains runtime getter coercions and defers ambiguous image fields. Common mode does not add pixel-unit syntax. EMEE graphical numeric arguments may use a terminal `px` unit; S020 inserts one ASCII space only after a proven numeric expression and preserves the unit's case. Invalid forms such as `10px` are left unchanged, and ordinary identifiers containing `px` are unaffected. Unknown EMEE image fields remain opaque without symbol resolution.

Graphics numeric fields reject trailing operators and incomplete constant-only expressions, including ternaries that cross a parenthesis boundary. Fields containing unresolved identifiers keep their existing macro-sensitive analysis. Incomplete expressions before a terminal pixel unit, such as `1+px`, retain their argument bytes and produce an unsupported diagnostic. A FORM expression containing the mandatory inline `;!;` marker is recognized but preserved completely, including its edge padding; other proven islands can still be formatted. L007 also separates declarations from supported raw output and FORM-producing statements without changing their payloads.

Graphics numeric fields permit strings and FORM within function arguments, such as `PRINT_SPACE STRLENS("abc")`. Base/common protect proven top-level string values; EMEE preserves its getter coercions, and ambiguous image tails remain opaque. Nested FORM analysis reuses source-scoped parsing information and verifies all edits at the enclosing expression boundary; independent top-level FORM islands retain separate verification and error handling. A mandatory `;!;` marker is visible to the token classifier, but its bytes and adjacent gaps remain intact; it does not turn the complete command into an untyped raw payload.

## Control flow and data blocks

Conditions, loops, numeric outputs, and string-output commands also check proven field types. RETURN checks every field; ordinary scalar commands check the first field and preserve ignored surplus with a warning. Explicitly analyzed continuations retain trusted return, CASE selector, and TRYGOTOLIST context, including a selector declared in a continuation. Unsupported joined declarations preserve their containing function or file; advisory declaration warnings retain established context. Executable markers and unresolved paths defer context checks. After a preprocessor join, selector types are retained only when every possible branch proves the same type. Diagnostic positions retain their physical rows even at empty joins. Trusted #FUNCTION/#FUNCTIONS declarations require numeric/string RETURNF values; RETURN and RETURNFORM are unsupported in methods, and proven RETURNF expressions are unsupported in ordinary functions. Bare numeric conditions retain runtime defaults, while explicit leading empty fields are unsupported. RETURN and CASE reject interior empty fields and permit one trailing comma; string prints, SELECTCASE, and CASE require an expression. FOR requires a mutable numeric non-character counter and an end expression, while permitting an omitted start and an absent step. One terminal comma is ignored; an explicitly empty fourth field is unsupported. Proven surplus fields produce `ignored_arguments` and preserve the complete FOR body. PRINTDATA* output variables are numeric, STRDATA outputs are strings, and SWAP requires matching proven variable types. SELECTCASE/CASE compare proven selector and operand types, including bounded IS/TO forms; uncertain preprocessor paths defer the comparison. These checks stop at possible macros. VARSET/CVARSET/POWER apply ordinary expression shape checks to proven fields before possible macros. Specialized handlers validate required prefix fields first; known runtime-ignored surplus fields emit `ignored_arguments` and preserve the complete specialized body. Other failures after a possible macro preserve the body without guessing its expanded positions; valid raw shapes retain their formatting coverage.

Proven empty PRINTDATA/STRDATA/DATALIST blocks produce advisory `empty_data` warnings at their closers. Data-presence facts survive a preprocessor join only when all possible paths agree. Uncertain data presence suppresses the warning; an empty child DATALIST still counts as an entry in its parent.

## Assignments and variable roles

Plain assignment RHS padding uses ASCII space and TAB only. Leading U+3000 remains literal payload for both known and unresolved destination types, regardless of `--allow-fullwidth-space`.

SAVEVAR permits one terminal comma without adding an empty argument. Interior omissions and a double terminal comma remain unsupported, and every source comma is retained.

Plain `=` and `==` assignments can format the proven LHS expression and the gaps immediately around the operator; the RHS interior remains opaque for every destination type. Compound assignment RHS expressions can use the proven expression rules. TIMES formats its first variable field and preserves the original spelling of its real coefficient. PRINTDATA* and STRDATA accept only their optional variable heads; SPLIT accepts three or four fields with variable outputs and SWAP uses two variable fields. EMEE accepts BINPUT, BINPUTS, ONEBINPUT, and ONEBINPUTS aliases. SAVEVAR formats two string-expression fields followed by mutable non-character variable fields. Proven local builtins (ARG, ARGS, LOCAL, LOCALS) and calculated WINDOW_TITLE are ineligible save targets; WINDOW_TITLE remains assignable. Direct literals and exact known system variables receive limited field-type checks in SAVEVAR, SPLIT, VARSET, CVARSET, POWER, and registered color, button, save, input, and array commands; unresolved symbols, aliases, and earlier potential macros prevent uncertain role inference. String setters and CVARSET named CSV selectors remain supported; CVARSET values must match the destination type. Known TIMES and bit-command destinations must be numeric, and known CVARSET destinations must be character variables. Proven immutable runtime variables are rejected in mutable roles, including the output array and count fields of SPLIT and HTML_TAGSPLIT. SAVEVAR checks duplicate variable identities, and SAVECHARA checks direct literal ID ranges and duplicates. Trusted method returns, exact event headers, same-file ERH declarations, and bounded LOCALSIZE constant expressions receive conservative validation. LOCALSIZE/LOCALSSIZE emit advisory suspicious_local_size warnings for proven-invalid constant expressions, including failed integer division and non-numeric results. Project constants, conditional declarations, and unsupported evaluation such as numeric string comparisons defer; event-function handling retains priority. Partially parsed TIMES coefficients and ignored scalar surplus preserve the complete argument body with warnings. Macro-bearing indexes defer uncertain destination checks. Bit and setter marker fields remain conservative; specialized handlers classify the token view of a single mandatory marker while preserving its source bytes. PRINTBUTTON reply fields accept either type; AWAIT and BREAKBUTTON remain unrestricted. EMEE INPUTS suffixes that the runtime warns about and ignores do not become formatter errors. Small shared handlers cover LOADCHARA/LOADVAR string expressions, tooltip delay/duration integers, ENCODETOUNI, PRINTCPERLINE, and optional-variable SAVENOS. Macros, unresolved aliases or configuration, optional or stacked executable markers, special markers, unknown commands, and raw PRINT/DATA payloads remain opaque. Continuation bodies are inspected only with an explicit continuation separator. A too-small raw argument count with an unresolved identifier preserves the argument body without guessing its macro expansion. Direct literals and known system-only counts retain their checks; registered fixed-field and timed-input commands accept one terminal comma; runtime-ignored surplus emits `ignored_arguments` and preserves the argument body after the required prefix has been validated. The formatter does not repair syntax or rewrite source text.

Exact uppercase bare builtin variables, including ARG/ARGS/LOCAL/LOCALS, carry bounded value, rank, character, and read-only metadata. Implicit assignments and increments reject proven immutable destinations; increments also reject proven string destinations. Plain assignment payloads and valid string compound operations retain their existing handling. Modern-only constants are recognized only in EMEE. Literal indexes may prove immutable variable identity; scoped or dynamic references and case variants defer. Single numeric or string index atoms also support bounded builtin type and index-count checks, including character target completion. String indexes are permitted only in builtin positions backed by CSV keyword dictionaries, including `CDFLAGNAME1`/`CDFLAGNAME2`; an implicit character target shifts the source position before this check. Macro-capable, scoped, and unresolved indexes defer; configured bounds and CSV contents are not checked. Proven grouped and indexed builtin references retain their backing rank and character role for array commands, CVARSET, FOR, and SORTCHARA. Scalar command and METHOD fields, PRINTV expressions, and FORM values, widths and conditions reject known rank-two or rank-three variables without required indexes. This includes consumed Any values and same-type METHOD fields; rank-one defaults, matrix references, and array-wide destinations remain valid.

SETBIT, CLEARBIT, and INVERTBIT preserve malformed leading or interior empty fields and direct string arguments with a diagnostic. Numeric literal destinations and bit index literals outside 0..63 are also diagnosed. The checks follow runtime radix and exponent semantics without changing numeric spelling. Identifier fields may expand through macros, so raw field counts, dynamic ranges, unknown variable types, and mutability are not inferred. A trailing comma remains valid. VARSET, CVARSET, and POWER also diagnose literal destinations and proven omissions in checked fields. These setters and bit commands diagnose proven arithmetic destinations and builtin method calls that cannot yield assignable variables; parentheses, unary plus, and unresolved macro forms remain supported. Optional fields, trailing commas, and ignored extra fields remain permitted. An omission after a potential macro preserves the argument body because field positions cannot be proven.

POWER requires three proven positional fields before ignored extras are considered. Specialized surplus fields emit `ignored_arguments` after required prefix validation and preserve the complete body; surplus handling is command-specific rather than a general too-many-argument rewrite.

## NUL and executable markers

Line-leading `;^;` is an ordinary comment in common/base mode and a mandatory executable marker in EMEE. Its payload bytes are preserved in both cases, while only EMEE applies its block or SIF state. Debug-dependent `;#;` remains conservative. Inline and header-tail `;^;` are ordinary comments in every dialect: their payload stays intact while a proven code prefix can be formatted.

NUL terminates raw FORM text and expressions at token boundaries; ignored suffix bytes remain unchanged. NUL inside a runtime identifier remains part of that identifier. Quoted strings, quoted FORM, and escape sequences interrupted by NUL produce diagnostics.

A single mandatory inline `;!;` marker is transparent to ordinary expression spacing, including PRINTV expressions. The marker and its adjacent gaps remain byte-for-byte intact; other proven gaps may change. FORM islands containing the marker remain wholly preserved, as do raw PRINTV atoms.

Mandatory inline markers participate in token classification without converting the entire command to an untyped raw payload. The marker bytes and adjacent gaps remain unchanged while proven gaps elsewhere may still be formatted.

## Partial formatting and errors

Uncertain structure preserves its containing function, allowing other functions in the same file to be formatted and written. If a selected expression cannot be tokenized safely, only its argument remains unchanged. F001 and F002 are global and still apply around unsupported bodies. A known structural, encoding, or edit-conflict error leaves the file unchanged with no changes. Unsupported formatting still returns exit code 2 so callers cannot mistake partial coverage for a complete check. If function boundaries cannot be trusted, only F001/F002 may change the decoded text. F001 leaves an empty file unchanged.

Once a function is preserved, ordinary statements within it are not inspected further. Later independent function headers are still validated. Diagnostics therefore describe the formatter's proven analysis boundary rather than every possible runtime error in opaque text.

## Resource limits

Formatter metadata has a 32 MiB accounting budget shared by physical and virtual source lines, edits (including their eventual change records), diagnostics, and column indexes. The budget charges line metadata before constructing its table and charges subsequent metadata before appending it; speculative or removed records do not refund it. Formatting is bounded to 512 structural levels, 512 preprocessor levels, and 65,536 retained preprocessor state units (one per state plus one per block frame). Conditional convergence proofs share a limit of 4,194,304 state/frame work units per file. Expression parsing allows 512 delimiter levels, 65,536 fields or tokens and 1 MiB of token or nested FORM fingerprint text per range, and 262,144 uncached tokens per source session. FORM parsing allows 128 levels and 4 MiB of retained fingerprints per source session. Canonical grammar whitespace does not count toward expression limits. Parsing limits apply wherever parsing is required, including structural checks with expression rules disabled; raw output, inactive debug FORM payloads, and preserved function bodies remain opaque. Changed results and virtual continuations are bounded to 64 MiB. Exceeding a bound produces a fatal `resource_limit` diagnostic and returns the original decoded source without changes. An unchanged input larger than 64 MiB remains pass-through when the selected rules do not parse or alter it.
