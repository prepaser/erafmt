# Formatting rules

The catalog in [`internal/format/rules.go`](../internal/format/rules.go) is the implementation source of truth. These 37 IDs are stable and must never be reused for another behavior. All catalog rules are enabled when `Options.Select` is nil; there is no separate default-enabled profile.

## Indentation and structure

| ID | Name | Purpose | Example |
| --- | --- | --- | --- |
| I001 | `function-indent` | Place trusted function headers at column zero. | `  @F` → `@F` |
| I002 | `declaration-indent` | Indent ERB declarations inside functions and keep ERH declarations at column zero. | `#DIM UserVar` → `    #DIM UserVar` |
| I003 | `label-indent` | Indent labels at the current statement depth. | `$L` → `    $L` |
| I004 | `instruction-indent` | Indent ordinary instructions and block boundaries with four spaces per level. SIF targets belong to I005. | `IF X` → `    IF X` |
| I005 | `sif-indent` | Indent the complete physical instruction targeted by SIF one level deeper. | `@F` / `    SIF X` / `        RETURN` remains canonical |
| I006 | `comment-indent` | Indent standalone comments at the current statement depth. | `; note` → `    ; note` |
| I007 | `continuation-indent` | Indent continuation delimiters with their logical statement. | `{` / `}` → `    {` / `    }` |
| I008 | `preprocessor-indent` | Place trusted standalone bracket preprocessor directives at column zero. | `    [IF FEATURE]` → `[IF FEATURE]` |

I007 owns both delimiter lines, including a continuation used as a SIF target. A normal physical SIF target is owned wholly by I005; I004 does not own a base portion. Ignoring I005 therefore leaves the target indentation unchanged. Preprocessor indentation does not touch continuation interiors, skipped bodies, unresolved directives, or other opaque lines. Continuation opener tails follow the runtime's Unicode whitespace check and retain their bytes; leading delimiter whitespace follows the configured grammar. Syntax mapping skips insertions at physical row starts, including rows with no existing indentation. Ordinary inline caret comments and literal caret text can be analyzed across explicitly joined rows; executable line-leading markers stay protected. Explicit joins retain proven function return modes, declaration, attribute and label state, SELECTCASE/CASE types and TRYGOTOLIST restrictions. Duplicate joined labels use the physical token position. Conditional diagnostics defer within each branch; after a join, selector types survive only when every possible path agrees. Statement diagnostics, including deferred SIF, block and preprocessor errors, use the physical token origin. The same mapping applies to statement nesting and retained preprocessor state limits. Continuation delimiter errors and unresolved separator-dependent dispatch retain their delimiter origins.

Adjacent instructions consisting of a single `;#;SIF` and a single `;#;` non-structural target are preserved together when their active and inactive paths leave the same structure. Assignments and prefix/postfix increments count as SET targets when their LHS is proven. Formatting then continues after the pair. Conditional `ELSEIF` insertion retains the surrounding IF structure. Preprocessor paths with differing final-branch state may join through a common path of proven instructions, including SET assignments and increments, when an unmarked `ENDIF` or `ENDSELECT` closes every path at the same depth with the same resulting structure. Other unresolved branch states retain whole-file preservation. Trusted BREAK/CONTINUE outside REPEAT, FOR, WHILE, or DO produce advisory `invalid_loop_control` warnings without changing formatting or exit codes. ERH accepts only DEFINE, DIM, and DIMS sharp directives; ERH FUNCTION(S), REF declarations, bracket preprocessing, and other sharp directives preserve the file except for F001/F002 and produce unsupported diagnostics.

Trusted ERB functions warn about duplicate or conflicting #SINGLE/#LATER/#PRI/#ONLY attributes and ignored event attributes outside events. #ONLY overrides earlier event attributes. Repeated #FUNCTION(S) declarations warn, and conflicting function kinds are unsupported. Trusted METHOD declarations whose function names start with a BMP Unicode decimal digit are unsupported and preserve their function; ordinary Unicode digit-leading functions and supplementary-plane digits remain accepted. Conditional or optional declarations defer state tracking. Event recognition uses the runtime event-name set; case variants retain configuration-dependent preservation without event warnings. TRYGOTOLIST FUNC rows cannot carry proven nonempty subnames or arguments; other TRY list variants retain their argument grammar.

ELSE/ELSEIF after ELSE and CASE/CASEELSE after CASEELSE retain their normal block transitions and produce advisory `branch_after_final` warnings when trusted and unconditional. Unmatched branches, cross-kind closers, and duplicate CATCH remain errors. Trusted unconditional nested REPEAT openers produce `nested_repeat` warnings. Warning metadata is merged conservatively across preprocessor paths and does not affect formatting or exit status.

## Expression and token spacing

| ID | Name | Purpose | Example |
| --- | --- | --- | --- |
| S001 | `command-spacing` | Use one space between a recognized command and its argument. | `IF\tA` → `IF A` |
| S002 | `binary-spacing` | Use one space around binary operators. | `A+B` → `A + B` |
| S003 | `ternary-spacing` | Use one space around ternary `?` and `#` operators. | `A?B#C` → `A ? B # C` |
| S004 | `unary-spacing` | Attach unary operators without merging distinct operator tokens. | `- A` → `-A` |
| S005 | `comma-spacing` | Remove spaces before commas and add one after them while preserving omitted arguments. | `F(A , B)` → `F(A, B)` |
| S006 | `delimiter-spacing` | Remove spaces before opening delimiters, inside opening delimiters, and before closing delimiters. | `F ( A )` → `F(A)` |
| S007 | `index-spacing` | Remove spaces around index colons. | `A[0 : 1]` → `A[0:1]` |
| S008 | `case-spacing` | Use one space around CASE `IS` and `TO` keywords. | `CASE IS   +1, 2   TO   3` → `CASE IS +1, 2 TO 3` |
| S009 | `token-spacing` | Normalize remaining expression token gaps while retaining required word separators. | `A  B` → `A B` |
| S010 | `assignment-left-spacing` | Use one space immediately before a proven assignment operator. | `A=1` → `A =1` |
| S011 | `assignment-right-spacing` | Use one ASCII space immediately after a proven assignment operator; leave the RHS interior opaque. | `A =  1` → `A = 1` |
| S012 | `declaration-word-spacing` | Use one space between recognized declaration keywords, modifiers, names, and object #DEFINE body separators. | `#DIM  UserVar` → `#DIM UserVar` |
| S013 | `declaration-default-spacing` | Use one space around declaration and parameter default equals signs. | `ARG:0=1` → `ARG:0 = 1` |
| S014 | `inline-comment-spacing` | Use one ASCII space before a proven attached ordinary comment. | `IF A; note` → `IF A ; note` |
| S015 | `comment-prefix-spacing` | Use one space after an ordinary standalone or inline comment prefix when its code end is proven. | `;note` → `; note` |
| S016 | `preprocessor-field-spacing` | Use one space between a trusted bracket directive and its operand. | `[IF   FEATURE]` → `[IF FEATURE]` |
| S017 | `form-placeholder-padding` | Remove edge padding inside proven FORM placeholders. | `PRINTFORM { A+1 }` → `PRINTFORM {A+1}` |
| S018 | `label-marker-spacing` | Remove ASCII padding between a trusted `@` or `$` marker and its identifier. | `@  F` → `@F` |
| S019 | `form-condition-spacing` | Normalize the condition-side spacing of a FORM conditional. | `\@A?yes#no\@` → `\@ A ?yes#no\@` |
| S020 | `pixel-unit-spacing` | Use one ASCII space between a proven EMEE graphical numeric expression and its terminal `px` unit, preserving unit case. | `PRINT_SPACE (W+1)px` → `PRINT_SPACE (W+1) px` |

Expression gaps have one owner. S006 owns closing delimiters and opening-delimiter interiors. S005 owns comma adjacency except when the next token is a closing delimiter, which belongs to S006. S007 owns index colons. S008 owns CASE keywords. S003 takes precedence over S002 for ternary operators; S002 owns other binary operators; S004 owns unary operators; S009 owns remaining word gaps. S010 and S011 own only the gaps immediately outside a proven assignment operator, preserving the complete operator lexeme. S012 and S013 own declaration and signature gaps. S016 owns bracket directive fields. S017 owns FORM placeholder edges. S018 owns only trusted `@`/`$` marker padding. S019 owns one ASCII space after the opening `\@` and one before `?`; text after `?`, around `#`, and before the closing `\@` is a literal branch and remains unchanged. S020 owns only the separator before a terminal `px` unit in a proven EMEE graphical numeric field; it never repairs invalid forms such as `10px`, and ordinary identifiers containing `px` are unchanged.

The expression grammar covers recognized common expression commands, assignments, compound assignment RHS expressions, FOR and list contexts, calls, signatures, declarations, qualified variables such as `LOCAL@FUNC:0`, and full FORM islands. Bare conditional FORM atoms may omit the false branch. Quoted `@` strings, PRINTFORM, DATAFORM, RETURNFORM, CALLFORM, PRINTV, and nullable REUSELASTLINE contexts preserve literal spans, escapes, width/alignment fields, and placeholder edge boundaries. Placeholders require a nonempty first expression and accept at most three top-level fields; an alignment field requires a nonempty width. One trailing empty field remains valid, and macro-capable alignment names are not resolved. FORM and SELECTCASE/CASE type checks use the selected builtin catalog, including proven parenthesized and indexed compound expressions. A mandatory `;!;` marker remains visible to token classification while its bytes and adjacent gaps stay intact; it does not make the complete command an untyped raw payload. S020 is limited to EMEE graphical numeric fields and does not apply to common FORM syntax.

Proven FORM value types must match their island: braces take integers, percent islands take strings, and widths and conditional expressions take integers. A type mismatch preserves that island while other proven islands remain eligible. Any macro-capable token suppresses type inference, including a variable index that can expand into an outer operator. Unknown first fields also suppress later width-role inference. Exact builtin names in the selected dialect are invalid in proven alignment slots; LEFT/RIGHT punctuation tails are invalid, while unknown names and identifier-only macro tails remain unresolved. Single ordinary quoted PRINTFORMS-family and direct builtin STRFORM literals without source escapes reuse S002-S009, S017, and S019 within FORM islands after argument validation. Nested STRFORM calls remain unresolved because user methods may override them. Literal text and outer quotes remain preserved. Dynamic, concatenated, escaped, aliased, and marked forms retain their existing handling; EMEE PRINTFORMSN keeps its registered scalar validation and surplus rollback. DEBUGPRINTFORM/DEBUGPRINTFORML payloads remain opaque without lexical or semantic FORM diagnostics because normal runtime mode discards their arguments.

Proven constant curly widths whose runtime signed 32-bit cast is negative produce advisory `suspicious_form_width` diagnostics and preserve the affected island. Percent widths, unresolved value types, calls, and dynamic widths defer this check. The warning also propagates from proven graphics arguments and nested FORM strings. It does not replace independent FORM syntax errors or impose a positive width limit.

Exact uppercase bare builtin variables carry bounded value, rank, character, and read-only metadata for command roles. ITEMPRICE, name arrays, GAMEBASE constants, and other immutable runtime values are rejected in proven mutable roles, while read roles such as VARSIZE remain valid. Modern-only constants are recognized only in EMEE. Qualified forms, case variants, and unknown names defer new role inference; single numeric/string index atoms support bounded type and arity proof, including character target completion. String indexes require a builtin CSV keyword position, including CDFLAGNAME1/CDFLAGNAME2, after accounting for an implicit character target. Complete indexed builtins retain their value type with parenthesized or builtin-only indexes, including inside compound expressions. Proven string increment operands are rejected. Bounded numeric indexes retain exact immutable builtin identity for mutable command roles without resolving index validity; calls, scoped names, markers, and macro-capable indexes defer new proof. No configured bounds or CSV contents are checked. Proven grouped and indexed builtin references retain their backing rank and character role for array commands, CVARSET, FOR, and SORTCHARA. Scalar command and METHOD fields, PRINTV expressions, and FORM values, widths and conditions reject known rank-two or rank-three variables without required indexes, including consumed Any and same-type fields. Rank-one defaults, matrix references, and array-wide destinations remain valid.

Literal-only expressions receive bounded completeness and compound type checks. LOCALSIZE/LOCALSSIZE additionally evaluate bounded integer-only constant expressions using runtime overflow and shift semantics; proven division failures and non-numeric results produce advisory suspicious_local_size warnings; unresolved identifiers, conditional declarations, and unsupported evaluation defer. Proven invalid index types, arity, and expression shapes propagate through compound builtin indexes instead of becoming unknown. Ordinary expressions, compound assignment RHS expressions, call/METHOD fields, PRINTV, and FORM islands reject proven adjacent operands in either order, assignment operators, invalid builtin dot, colon or bracket boundaries, malformed indexed suffixes, incomplete operator operands, string increments, and misplaced CASE keywords. CASE accepts numeric mutable prefix/postfix increments in IS/TO operands, rejects `?`/`#` as IS operators, and checks missing, repeated, and nested IS/TO components and reserved TO used as an unparenthesized builtin index; grouping parentheses reject nested commas while possible function-call arguments defer. Unknown identifiers, mandatory markers, bare calls, scoped references, and deeply nested expressions defer the proof. Bare numeric conditions preserve runtime defaults; explicit leading omissions are unsupported. RETURN and CASE reject interior omissions but permit one trailing comma. String prints, SELECTCASE, and CASE require an expression. SELECTCASE/CASE compare proven types, including IS/TO bounds, with conservative preprocessor joins.

The formatter uses field-specific handlers for common command families, including `SETCOLOR`/`SETBGCOLOR`, font and HTML commands, print buttons, waits, character operations, array operations, string helpers, and FORM-producing debug/output commands. Mixed variable and expression fields are changed only after their structure is proven. EMEE registers the `PRINTN`, `PRINTVN`, `PRINTSN`, `PRINTFORMN`, and `PRINTFORMSN` variants; other dialects preserve those unknown variants and their payloads. Direct METHOD statements use 151 shared contracts and 93 EMEE additions or overrides for proven arity and argument-type checks, deferring macros, markers, FORM, and nested calls. SUBSTRING/U, STRFIND/U, TOSTR, and MONEYSTR accept bounded nullable suffixes; HTML_POPPRINTINGSTR accepts no arguments. HTML_GETPRINTEDSTR accepts an omitted line number but rejects an explicit empty one. REPLACE accepts three string fields in common/base mode and an optional numeric fourth field in EMEE. Proven EMEE mode 1 requires a mutable non-character one-dimensional string replacement array. EMEE INRANGECARRAY requires one-dimensional character data; common/base keep multidimensional character references. Whole-array METHOD outputs reject character backing storage while scalar XML mutation targets retain CSTR support. MIN/MAX check numeric variadic fields, and GROUPMATCH/NOSAMES/ALLSAMES check matching proven types. SAVETEXT/LOADTEXT use numeric file indexes in common/base mode and permit string paths in EMEE; common/base reject explicit optional nulls. EMEE also validates SETVAR/VARSETEX, bounded data-table calls, ENUMFILES, MOVETEXTBOX/RESUMETEXTBOX, and GETMETH(S) scalar prefixes, deferring dynamic target and reference semantics. Supplied VARSETEX range fields must have values. GDRAWSPRITE/GDRAWG accept bounded numeric 2D/3D matrix references, including explicit character targets; EMEE GDRAWG alone permits an explicit empty matrix tail. Character-list commands and SAVECHARA validate every argument without a 255-field limit. DT_COLUMN_OPTIONS accepts complete DEFAULT/value pairs with one terminal comma. Registered fixed-field and timed-input commands accept one terminal comma, preserving genuine omitted fields and ignored surplus warnings. Array modes and runtime value constraints remain unresolved. Expression calls can resolve to user methods, so graphics do not infer their return type from builtin names.

Shared no-argument commands include color/font resets, save/load, global resets, and restart. `AWAIT`, `INPUTMOUSEKEY`, and `RANDOMIZE` accept optional integer expressions. Raw-string commands such as `BEGIN`, `CALLEVENT`, `ALIGNMENT`, color-name commands, `STRLEN`, and `STRLENU` preserve the entire command separator and payload; S001, L002, S014, and S015 do not edit those raw fields. Parenthesized and numeric unary-plus variables are supported in command fields without changing implicit assignment recognition. Variable roles reject bracket indexes and proven residual expressions such as `RESULT:0+1`; parenthesized indexes such as `RESULT:(0+1)` remain valid, and general expressions keep their existing arithmetic grammar. `VARSIZE` reads a bare array identifier and rejects the `RAND` pseudo-array. Proven ignored suffixes produce `ignored_arguments` and preserve the complete command body; macro-dependent names and fields retain their conservative handling. The suffix is ignored text, not a dimension argument. EMEE sound, tooltip, HTML island, background, and data-table handlers use their own field grammars; background FORM fields preserve literal commas and semicolons.

Builtin METHOD functions are recognized through exact dialect allowlists. Common mode uses the base/modern intersection; the base allowlist has 160 direct names and the modern allowlist has 266. GETNUM, FINDELEMENT/FINDLASTELEMENT, ARRAYMSORT, RAND, SUMARRAY/SUMCARRAY, MATCH/CMATCH, INRANGEARRAY/INRANGECARRAY, and STRJOIN validate proven reference, rank, type, and nullable field contracts. STRJOIN rejects proven character-backed string arrays; numeric character arrays are rejected only when an explicit positive range length proves the incompatible consumer path. GETNUM accepts an optional third numeric scope field only in EMEE; a provided scope cannot be empty. EMEE validates REGEXPMATCH output variants, DT_SELECT output arrays, and XML_GET/XML_ADDNODE/XML_REMOVENODE including BYNAME forms. Proven reference type, mutability, backing-array rank, and required field presence are checked; indexed array references remain accepted. XML/regex contents and project-dependent schemas remain unresolved. CSV lookup methods check their numeric prefix and optional SP-character flag. FINDCHARA/FINDLASTCHARA require a character-data reference and a matching value type, followed by optional numeric bounds; FIND_CHARADATA accepts zero fields or one string pattern. MAXARRAY/MINARRAY require numeric one-dimensional arrays; MAXCARRAY/MINCARRAY also require character data. All four accept read-only arrays and up to two optional numeric bounds. GETBIT checks direct integer bit indexes against 0..63; calculated or unresolved indexes defer range proof. Read roles accept immutable arrays; ARRAYMSORT requires mutable non-character arrays and a one-dimensional first array. Secondary arrays may have up to two dimensions in Emuera1824 and three in EMEE; common mode retains the modern secondary-array shape. INRANGE* requires both bounds, accepts the base-only ignored sixth field in Emuera1824, and uses a five-field maximum in common/EMEE. Unknown declarations, scoped references and dynamic indexes defer. The remaining METHOD signatures are checked by the runtime. Active METHOD names retain instruction precedence and cannot be treated as implicit assignment destinations. The formatter recognizes only registered names, and explicit handlers or raw commands take precedence. OUTPUTLOG keeps its base instruction role and uses METHOD parsing in EMEE. TIMES formats its first variable field and preserves the original spelling of its real coefficient. Decimal forms that the runtime partially parses, including 1e+2 and 1+2, produce runtime_numeric warnings and preserve the complete body; they are never repaired or reinterpreted. PRINTDATA* and STRDATA accept only optional variable heads, SPLIT accepts three or four fields with mutable variable outputs, and HTML_TAGSPLIT also rejects proven read-only output arrays and count destinations. SWAP uses two variable fields. EMEE aliases BINPUT, BINPUTS, ONEBINPUT, and ONEBINPUTS. Shared handlers cover LOADCHARA/LOADVAR string expressions, tooltip delay/duration integers, ENCODETOUNI, PRINTCPERLINE, and optional-variable SAVENOS.

Graphics handlers are conservative. The base/common `PRINT_IMG` form accepts one string expression, `PRINT_RECT` accepts one or four safe expressions, and `PRINT_SPACE` accepts one; valid trailing commas remain valid. Base/common graphics reject proven numeric image names and proven string values in numeric fields; string comparisons with numeric results remain valid. EMEE permits its string/FORM getter coercions and defers ambiguous image fields. Common mode does not add pixel-unit syntax. Numeric fields permit strings and FORM within function arguments, including nested parentheses; base/common reject proven string values while accepting numeric string comparisons. EMEE graphical numeric arguments may use a terminal `px` unit; S020 inserts one ASCII space only after a proven numeric expression and preserves the unit's case. Invalid forms such as `10px` are left unchanged, and ordinary identifiers containing `px` are unaffected. Unknown EMEE image fields remain opaque without symbol resolution. Mandatory markers are removed only from the token view, so identifiers on either side never concatenate. S020 preserves a unit gap immediately following ;!;. Base/common direct graphics literals outside 0..2147483647 produce suspicious_graphics_range warnings and retain their body; EMEE uses different signed conversion semantics.

Graphics numeric fields reject trailing operators and incomplete constant-only grouped or ternary expressions; identifier-bearing fields retain macro-sensitive analysis. Pixel-unit prefixes must be complete expressions; unfinished forms such as `1+px` are preserved with a diagnostic. Indexed and qualified variables, empty method calls, unary and postfix operators, and balanced ternary expressions retain their existing token spelling. FORM islands containing the mandatory inline `;!;` marker retain their complete bytes and padding while neighboring proven islands remain eligible for correction. Unicode digit-leading function and goto names and marker-only header tails are recognized without changing the marker bytes.

Plain `=` and `==` assignments can format the proven LHS expression and the gaps immediately around the operator; the RHS interior remains opaque for every destination type. Compound assignment RHS expressions can use S002-S009 after their grammar is proven. VARI/VARS, macros, unresolved aliases or configuration, optional or stacked executable markers, special markers, unknown commands, and raw PRINT/DATA payloads remain opaque. Continuation bodies are inspected only with an explicit continuation separator. Width/alignment token spelling is retained while expression spacing rules control proven gaps. An inactive rule leaves its original bytes untouched. Every selected expression edit is committed only after the resulting expression is lexed again with the same token sequence.

SETBIT, CLEARBIT, and INVERTBIT use S002-S009 for proven expression gaps. When expression or code/comment layout parsing is selected, omitted leading or interior fields, direct string arguments, numeric literal destinations, and bit index literals outside 0..63 produce unsupported diagnostics and preserve the argument bytes. Numeric checks follow runtime radix and exponent semantics. A trailing comma is valid; identifier fields may expand through macros, so raw argument counts, dynamic ranges, unknown types, and mutability remain unresolved. VARSET/CVARSET/POWER apply ordinary expression shape checks to proven fields before possible macros. VARSET, CVARSET, and POWER similarly diagnose literal destinations and proven omissions in checked fields, while permitting optional fields and one trailing comma. Proven ignored extra fields emit `ignored_arguments` and preserve the complete body; macro-dependent prefixes or tails defer this warning. Omissions after potential macros preserve the argument body without inferring field positions. SAVEVAR uses two string-expression fields followed by mutable non-character variables. Proven ARG, ARGS, LOCAL, LOCALS and calculated WINDOW_TITLE targets are rejected; WINDOW_TITLE remains mutable for ordinary assignments. Proven immutable targets and repeated builtin variable identities are unsupported, including repeated references to different literal indexes of the same variable. SAVECHARA checks direct integer IDs for the range 0..2147483647 and duplicates, allowing one trailing comma; general expressions and unresolved IDs defer. Narrow literal and exact system-variable type checks cover SAVEVAR, SPLIT, VARSET, CVARSET, POWER, and registered color, button, save, timed-input, and array fields. VARSET/CVARSET values must match their known destination type, and CVARSET selectors may be named CSV strings. Known TIMES and bit-command destinations must be numeric; known CVARSET destinations must be character variables. Macro-bearing indexes and mandatory markers defer these new destination checks. Unresolved symbols or earlier potential macros prevent uncertain type and field-role inference. A too-small field count with an unresolved identifier preserves the body without expanding it; direct FORM atoms are single fields. PRINTBUTTON reply fields and AWAIT/BREAKBUTTON remain unrestricted. Runtime-ignored EMEE INPUTS suffix types are not formatter errors.

Conditions, loops, numeric-output commands, and string-print families use the same bounded type knowledge. RETURN checks all fields; other scalar builders check the first and keep ignored-extra policy. Trusted #FUNCTION and #FUNCTIONS declarations require numeric and string RETURNF values respectively. RETURN and RETURNFORM are unsupported inside methods; proven RETURNF expressions are unsupported in ordinary functions. Optional, conditional, aliased, and unproven attribute state defers these checks. Complete explicitly joined sharp declarations commit the same proven state and preservation scope as physical declarations. Advisory declaration warnings retain established function and duplicate-declaration context. Exact runtime system/event labels cannot declare methods. FOR checks its mutable numeric non-character counter and required end, permitting an omitted start and an absent step. One terminal comma is ignored; an explicitly empty fourth field is unsupported. Proven surplus fields produce `ignored_arguments` and preserve the complete FOR body. PRINTDATA* takes numeric output variables, STRDATA takes string outputs, and SWAP checks matching proven variable types. HTML_PRINT takes a string head; its numeric second field is checked only in EMEE, as are the string/numeric HTML_PRINT_ISLAND and PLAYSOUND fields. Failed positional checks after possible macros in SPLIT, SWAP, ARRAYSORT, SORTCHARA, and HTML_TAGSPLIT preserve the argument body quietly. Valid unknown variable/array shapes still format. FORWARD/BACK can themselves be macros, so later sort positions are not inferred from their raw spelling.

A single mandatory inline `;!;` marker is transparent to ordinary expression classification. S002-S009 may format gaps away from it, including PRINTV expression gaps, while the marker and both adjacent gaps remain intact. Marker-containing FORM islands and PRINTV raw atoms remain unchanged. Optional and stacked markers retain their opaque behavior. Inline and header-tail `;^;` are ordinary comments in every dialect and preserve their payload while allowing proven prefix spacing. Line-leading `;^;` remains executable only in EMEE.

POWER requires three proven positional fields before ignored extras are considered. Specialized handlers validate required prefix fields first; known runtime-ignored surplus fields emit `ignored_arguments` and preserve the complete body.

S001, S005, S006, L002, and S014 preserve literal U+3000 and complete escape sequences in call targets; escaped punctuation stays literal, while actual argument-expression whitespace remains eligible for normalization. S011 preserves leading U+3000 in plain assignment payloads. EMEE background FORM commands retain literal TAB/U+3000 after the consumed command separator, while SAVEVAR permits one terminal comma. See [Formatting behavior](formatting.md) for these boundaries.

## Line and file layout

| ID | Name | Purpose | Example |
| --- | --- | --- | --- |
| L001 | `blank-line-whitespace` | Remove grammar whitespace from surviving ordinary blank lines. | `  ` → `` |
| L002 | `code-trailing-whitespace` | Remove trailing grammar whitespace from proven ordinary code. | `RETURN 1   ` → `RETURN 1` |
| L003 | `comment-trailing-whitespace` | Remove trailing ASCII spaces and tabs from ordinary comments. | `; note   ` → `; note` |
| L004 | `function-separation` | Keep exactly one blank line before each subsequent trusted function and its attached ordinary comment group. | `RETURN 0` / `@G` → `RETURN 0` / blank / `@G` |
| L005 | `blank-line-runs` | Reduce ordinary blank-line runs to one blank line outside function boundaries. | `A` / blank / blank / `B` → `A` / blank / `B` |
| L006 | `file-boundary-blank-lines` | Remove ordinary blank-line runs at the beginning and end of a file. | blank / `@F` / blank → `@F` |
| L007 | `declaration-body-separation` | Insert one blank line between a trusted leading ERB `#DIM`/`#DIMS` prologue and the function body. | `#DIM UserVar` / `RETURN 0` → `#DIM UserVar` / blank / `RETURN 0` |
| F001 | `final-newline` | Add a final newline to a nonempty rendered file. | `@F` → `@F\n` |
| F002 | `line-ending-normalization` | Convert physical line endings to LF or the selected CRLF style. | `A\r\nB\n` with LF → `A\nB\n` |

L006 owns only ordinary file-edge blank lines. It does not delete continuation interiors, skipped lines, protected or opaque regions, or the contents of a file whose structure cannot be trusted. L001 acts on blank-line bodies that survive L004-L007. With F002 disabled, L001 preserves a blank line's whitespace when deleting it would merge a preceding lone CR and its LF into one CRLF. L004 inserts exactly one blank line at a trusted next `@` boundary and keeps the separation block at indentation zero. Explicitly joined function headers use their continuation opener as the boundary, keeping the separator outside the interior rows. L005 owns runs of more than one ordinary blank line elsewhere; L007 inserts its declaration/body separator only when no blank line is already present. L007 applies only to trusted leading ERB `#DIM`/`#DIMS` prologues and is disabled for ERH, continuation or preprocessor regions, and unknown or guarded structures. A trailing comment group with uncertain declaration/body attachment prevents L007 insertion. Decorated comments, attached comment groups, skipped content, and opaque regions are protected. L002 requires a proven code span without a payload or comment suffix. L003 excludes decorated comments, executable markers, aliases, and protected comment artwork.

L006 retains leading blank lines when removing them would move a content U+FEFF to byte zero, where it would become an encoding BOM on the next invocation.

L007 recognizes the body boundary of supported raw output and FORM-producing statements independently of their payload opacity. Inserted separators precede indentation edits at the same source position; deleted blank lines retain only their owning layout correction.

With F002 disabled and explicit LF selected, L004/L007 insert two LF bytes after a lone CR: one completes the existing CRLF boundary and one represents the new blank line. This keeps the requested LF insertion stable on subsequent passes.

S015 also formats an ordinary `;` prefix on a proven code tail, using the same one-space rule as a standalone comment. It does not touch executable markers, aliases, decorative or protected comment blocks, or lines whose code end is uncertain. Inline `;;;...` and `; ;;...` tails retain their prefix and trailing whitespace; ordinary inline `;;note` may become `; ;note`.

F001 and F002 are global. They still apply when an unsupported function or opaque body exists, but a fatal encoding, structural, or edit-conflict error returns the original bytes with no changes. F001 leaves empty output unchanged, including an originally empty file or a file emptied by other rules. F002 defaults to LF; `Options.EOL` or `--eol=crlf` selects CRLF. `--eol=lf|crlf` selects style only and does not enable F002. When F002 is disabled, explicit EOL selection has priority for F001, L004, and L007; `DefaultEOL` uses the last surviving terminator and falls back to LF.

Proven zero literals, unary signs, and parentheses can accompany omitted local REF dimensions without changing their spelling or comma count. Nonzero direct local REF dimensions are unsupported. Ordinary DIM/DIMS direct literals outside 1..1,000,000, string literals, more than three proven dimensions, and proven total capacity above 1,000,000 produce `suspicious_dimension` warnings, preserving the declaration without affecting exit codes because a name macro can change field roles. A DIM/DIMS name is mandatory; exact uppercase builtin and runtime-reserved names are unsupported, and exact duplicate private names within one trusted function and proven global names within one ERH file produce `duplicate_declaration`. Private ERB names beginning with a BMP Unicode decimal digit are unsupported, while global ERH names and supplementary-plane leading digits retain their runtime behavior. DIM and DIMS share the global namespace; rejected or unresolved prior declarations are not recorded. Case variants, macros, aliases, and uncertain conditional paths defer. Macro-capable dimension fields suppress later role checks, and general arithmetic stops capacity accumulation. Empty LOCALSIZE/LOCALSSIZE directives produce `missing_local_size`, repeated proven valid non-event constant expressions produce `duplicate_local_size`, and nonempty directives in exact runtime event names produce `event_local_size`; constant values outside 1..2,147,483,646 produce advisory `suspicious_local_size` warnings and preserve the directive. DIM/DIMS initializer type/count mismatches, missing CONST initializers, REF or CHARADATA initializers, multidimensional initializers, and empty values produce advisory `suspicious_initializer` warnings and preserve the declaration. Repeated GLOBAL modifiers remain valid. Initializer cardinality uses bounded integer constant dimension expressions: CONST requires exactly the declared size, and ordinary one-dimensional initializers cannot exceed it. Unknown dimension or initializer expressions defer these checks. Proven modifier conflicts or invalid ERB/ERH modifier scopes produce `unsupported_syntax`; configuration-dependent storage rules remain unresolved. ERH function-style #DEFINE declarations with an immediate parenthesis after the name are unsupported and preserve the file. S012 normalizes object #DEFINE keyword/name/body separators while preserving its complete body. One terminal initializer comma is excluded from type/count checks; dimension commas and all source comma bytes remain unchanged. Proven ERH CHARADATA declarations above two dimensions produce `suspicious_dimension`. Exact uppercase event headers reject any raw argument delimiter or payload, including empty parentheses and an empty macro argument, and preserve the complete file as an invalid header. Square-bracket function subnames are also invalid structural headers, independently of rule selection. Case-dependent event names defer. No project symbol resolution or general constant evaluation is performed.

Runtime-warning preprocessing protects the whole file and permits only F001/F002 corrections. Nested skips, unmatched closers or branches, repeated `ELSE`, incomplete directives, and unclosed preprocessor regions produce `Unsupported` diagnostics without treating uncertain branch state as valid. IF/ELSEIF conditions must be one runtime identifier token; Unicode and digit-leading tokens remain accepted, while punctuation, quoted conditions, and extra operands preserve the file as unsupported. Fatal errors detected independently retain their original byte-preserving behavior.

Proven empty PRINTDATA/STRDATA/DATALIST blocks produce advisory `empty_data` warnings at their closers. Data-presence facts survive agreeing preprocessor branches; uncertain data presence suppresses the warning. A child DATALIST counts as a parent entry even when it is empty.

Explicitly joined, marker-free instructions can retain repeat, final-branch, and DATA facts when their syntax and physical edit mapping are proven. Warnings retain physical source positions; conditional metadata survives only when every possible branch agrees. Continuation interiors remain excluded from global layout rules.

Proven runtime builtin defaults and indexes are rejected independently of read-only metadata; constant CSV and GAMEBASE values remain accepted. Exact builtin parameter destinations with reduced constant indexes produce advisory `duplicate_parameter` warnings. Configured continuation headers reuse these checks with physical diagnostic positions and preserve rejected header rows while formatting the body. Private symbols, macros, calls, and unresolved indexes defer.

Formatting stops before parsing more than 1 MiB of syntax in one logical statement or allocating edits beyond 512 structural or preprocessor levels, a 64 MiB changed result, or a 64 MiB virtual continuation. A fatal `resource_limit` diagnostic preserves the original source and produces no `Change` records. Larger unchanged inputs can pass through when the selected rules do not parse or alter them.

Exact duplicate `$` labels in trusted functions produce `duplicate_label`; uncertain conditional labels stop tracking. Proven nonpositive REPEAT counts produce `nonpositive_repeat`. Both are advisory and leave formatting enabled.

## Selection and explanations

`Format` remains the compatibility entry point and enables all 37 rules. `FormatWithOptions` accepts `Options{Select, Ignore, EOL, Dialect, AllowFullwidthSpace, ContinuationSeparator}`; nil `Select` means all catalog rules, an empty non-nil selection means none, and `Ignore` is applied afterward, so ignore wins. IDs are case-sensitive and never reused. `Rules()` returns the catalog used by the core and CLI.

`--select=all`, `--select=none`, or a comma-separated ID list controls selection. `--ignore=I004,S002` excludes IDs after selection. `--rules` prints the tab-separated catalog and accepts no input or other formatting options except `--diagnostic-format`. `--explain` writes one record per committed changed span to stderr using the original 1-based line and Unicode character column. `--diagnostic-format=json` emits JSON Lines on stderr; the default is text. `--allow-fullwidth-space` opts U+3000 into grammar whitespace handling; otherwise grammar whitespace means ASCII spaces and tabs. `--continuation-separator=TEXT` explicitly enables logical analysis across continuation rows with the literal TEXT separator; an empty TEXT is valid. TEXT must be UTF-8 without CR, LF, or NUL. Syntax edits preserve physical row boundaries and interior indentation, and edits spanning a row boundary are skipped. I007 controls delimiter indentation, and F002 controls line endings. Diagnostics describe invalid or unsupported input; `Change` records describe corrections and are not derived from diagnostics.

## Dialects

`CommonDialect` is the zero-value default. `Emuera1824` models the base 1.824 grammar; `EMEE` adds the extended input and print variants. Dialect selection controls only command and argument recognition. It does not activate rules, infer project symbols or types, expand aliases or macros, or rewrite source case. Common `INPUT`/`ONEINPUT` numeric forms accept up to three fields, while the base dialect accepts up to one. Common and EMEE timed input forms accept two to six fields, while the base dialect accepts two to four. `INPUTS`/`ONEINPUTS` remains a FORM-oriented command: common mode requires no top-level comma in its FORM, base mode treats the rest of the line as one FORM, and EMEE may add zero to two numeric suffix fields. Ambiguous or unsupported forms are preserved.

`CALLSHARP`, `FORCE_QUIT`, `FORCE_QUIT_AND_RESTART`, `QUIT_AND_RESTART`, `SKIPLOG`, `TRYCALLF`, and `TRYCALLFORMF` require EMEE. Common and base modes preserve their entire instruction line and report `unsupported_command` when coverage is enabled. Unavailable instruction names can still be proven implicit assignment destinations. `OUTPUTLOG` is a no-argument instruction in common/base mode, with extra payload preserved, and a METHOD in EMEE.

Unavailable modern-only METHOD names can also be implicit assignment/increment destinations in the legacy dialect, including optional SIF targets. Reserved instruction payloads retain their precedence.

The dialect setting does not change the preservation contract. Unresolved runtime boundaries, plain assignment RHS text, raw output bodies, VARI/VARS, macro bodies, unresolved aliases, and unproven argument structures remain opaque. Fullwidth boundaries require the explicit whitespace option. `--allow-fullwidth-space` changes only grammar boundary recognition and does not rewrite Unicode whitespace in literal text. Continuation rows remain opaque unless an explicit `--continuation-separator` or non-nil `Options.ContinuationSeparator` enables their logical analysis. Without a configured separator, uncertain command, function-header, or preprocessor identities preserve the affected function or file. Structural heads are tracked only when the first physical row proves their boundary; a bare token at the row end is not sealed because the separator also follows the last interior row. Exact markers, aliases, literal text, data payloads, and plain assignment RHS text remain byte-preserved; proven FORM expression islands retain their own formatting rules, including inside supported PRINTFORMS literals. Ordinary statements inside a preserved function are not inspected further; later independent function headers are still validated.
